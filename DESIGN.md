# Vibe of Duty — Design Document

> Живой документ. Обновляется по ходу реализации: при каждом изменении решений, архитектуры или статуса фич правим соответствующий раздел и добавляем запись в «Журнал изменений».

## 1. Обзор

Сетевой 3D-шутер от первого лица в духе Call of Duty на Godot 4.7.2.
Целевое железо: ноутбуки со встроенной графикой (iGPU), цель 60 FPS.

- Репозиторий: корень `vibe-of-duty/` (git). Документация и прочее лежат здесь.
- Godot-проект: `vibe-of-duty-p/`.
- Арт: пока блокаут (примитивы/CSG), но структура рассчитана на замену моделями из паков Synty.
- Звук: временные синтезированные заглушки; финальные звуки и музыку делает владелец проекта.

## 3. Геймплей (CoD-подобные механики)

### 3.1. Первая итерация
- Движение: ходьба, спринт, приседание, прыжок, скольжение (slide).
- Камера от первого лица, mouse look, настраиваемая чувствительность и FOV.
- Стрельба: хитскан, ADS (прицеливание), разброс, отдача, перезарядка.
- 2–3 оружия (винтовка, пистолет, дробовик/SMG), смена оружия.
- Здоровье, смерть, респаун в точках спавна своей команды.
- Килфид, счётчик убийств/смертей, счёт команд, таймер матча.
- Простой HUD: здоровье, патроны, прицел, килфид, счёт.

### 3.2. Позже
- Гранаты и другие снаряды, перки/киллстрики, режимы (Domination и т. п.), боты, лобби.

## 4. Сеть

### 4.1. Архитектура
- Авторитетный сервер: вся игровая логика (урон, смерть, счёт) решается на сервере.
- Транспорт: `ENetMultiplayerPeer`. Сервер может быть headless (`--headless --server`) или хостом-клиентом.
- Тикрейт симуляции: фиксированный (план: 60 Hz физика, отправка снапшотов 20–30 Hz).

### 4.2. Движение игрока
- Клиент: сбор ввода → отправка команд на сервер с номером тика → локальное предсказание.
- Сервер: применяет ввод по тикам, рассылает снапшоты состояния.
- Клиент: реконсиляция (откат и повтор невыстоявших команд) при расхождении.
- Остальные игроки у клиента: интерполяция между снапшотами (задержка интерполяции ~100 мс).

### 4.3. Стрельба
- Клиент отправляет событие выстрела (направление, тик/время).
- Сервер выполняет lag compensation: откатывает хитбоксы игроков на время, соответствующее виду стрелка, затем делает raycast.
- Сервер рассылает результат (попадание, урон, смерть); клиент показывает эффекты предсказанно.

### 4.4. Принципы
- Никогда не доверять клиенту: проверка темпа стрельбы, патронов, скорости.
- Сетевой код отделён от игровой логики там, где возможно (чтобы тестировать без сцены).
- Тестирование: сервер + 2 клиента локально, имитация задержки/потерь.

## 5. Арт и подготовка к Synty

- Блокаут: CSG и примитивы, серый/цветной материал по назначению.
- Каждая сущность — отдельная сцена с корнем-логикой и сменным визуальным узлом `Visual` (`PlayerVisual`, `WeaponVisual`, `PropVisual`). Замена на Synty-меш = подмена дочерней сцены без правки кода.
- Хитбоксы отделены от визуала (капсулы/боксы на отдельных `Area3D`/`CollisionShape3D`), чтобы смена модели не ломала геймплей.
- Точки привязки: `Muzzle`, `HandR`, `HandL`, `Head` — задаются маркерами (`Marker3D`).
- Пак: **Synty POLYGON Battle Royale** (уже сконвертирован под Godot: `.tscn`-префабы, меши `extracted/`, материалы `.tres`). Лежит в `assets/` (`Prefabs/`, `models/`, `materials/`, `textures/`). Проверено в Godot 4.7.2: префабы загружаются, импорт проходит.
  - Персонажи: 15 готовых (`Prefabs/Characters/Characters/`), Skeleton3D на 50 костей, ~1.6k трис на модель, **анимаций в префабах нет** (`AnimationPlayer` пуст) — нужен отдельный набор (Mixamo/свой), ретаргет на скелет Synty.
  - Оружие: ~55 префабов (винтовки, SMG, дробовик, снайперки, пистолеты, гранаты, РПГ), каждое из частей (Mag, Slide, Sight, Flash…); в префабе есть `MeshCollider` (StaticBody3D) — для viewmodel/руки в руках его надо убирать.
  - Пути внутри `.tscn`/`.tres` (`res://Assets/PolygonBattleRoyale/...`) исправлены на реальные (`res://assets/models|materials|textures/...`); все 415 сцен/ресурсов грузятся без ошибок. Остатки старых путей есть только в служебных `.depren` и нескольких бинарных `.res` бронемашины (грузятся по UID, не критично).
  - Материалы — `StandardMaterial3D` с текстурной палитрой; для iGPU хорошо подходят.
  - Нет рук от первого лица (arms viewmodel) — используем ретаргет или отдельные руки/упрощённый viewmodel.
- Папки ассетов: `assets/` (модели, текстуры, материалы; заглушки в `assets/placeholder/`), `audioSFX/`, `music/`.

## 6. Производительность (iGPU)

- Рендерер: Compatibility или Forward Mobile — финальный выбор по замерам.
- Без глобального освещения реального времени, SSR, SSAO; тени ограничены (один directional, малый каскад).
- Запечённое освещение (LightmapGI) или простое окружение; ограничение draw calls, использование MultiMesh.
- Бюджет: 60 FPS на iGPU; профилирование через встроенный профайлер и Monitors.

## 7. Звук

- Единая точка: автолоад `Audio` с методом `play(id, position?)`.
- Реестр `id → ресурс`. Сейчас ресурсы — процедурные заглушки; позже владелец подменяет файлы без правки вызовов.
- Шины: Master / SFX / Music / UI, громкость в настройках.

## 8. Структура проекта (план)

```
vibe-of-duty/                 # корень репозитория
├─ DESIGN.md                  # этот документ
├─ .gitignore, .gitattributes
└─ vibe-of-duty-p/            # проект Godot (res://)
   ├─ project.godot
   ├─ prefabs/                # сцены (.tscn) — «префабы»
   │  ├─ player/  weapons/  levels/  ui/  fx/
   ├─ scripts/                # весь GDScript
   │  ├─ autoload/  net/  player/  weapons/  game/  ui/
   ├─ assets/                 # визуальные ассеты
   │  ├─ models/  textures/  materials/
   │  └─ placeholder/         # блокаут-заглушки (заменяются Synty)
   ├─ audioSFX/               # звуковые эффекты
   │  ├─ weapons/  player/  ui/  ambient/
   └─ music/                  # музыка
```

Правила: сцены лежат только в `prefabs/`, скрипты только в `scripts/` (скрипт сцены не кладём рядом с ней). Пустые папки хранятся через `.gitkeep`.

Автолоады (план): `Net` (подключение/хост), `Game` (состояние матча), `Audio`, `Settings`.
