# Статистика боёв и режим «FFA рандомное оружие»

> Зачем: TTK и баланс по живым людям, а не по ботам (`Docs/balance/` — боты). Какое оружие и с какими карточками чаще побеждает, какое проигрывает.

## Сбор

- Пишет только сервер (хост или выделенный), `scripts/net/match_stats.gd` (`MatchStats`, создаёт `NetWorld`). Клиенты ничего не пишут.
- Пишется, только если хост включил «Записывать статистику боёв» в разделе «Тестирование» (`Game.record_stats`; выделенный сервер и автотесты — `--stats`). На тренировках не пишется.
- Файл на запуск уровня: `user://stats/<дата>_<время>.jsonl` — на Windows `%APPDATA%\Godot\app_userdata\vibe-of-duty-p\stats\`. Путь печатается в консоль при старте. Строка = JSON-объект, поле `e` — событие, `t` — секунды от начала файла, `m` — номер матча в файле. Пишется сразу (flush), закрытое окно данных не теряет.
- Вариант оружия (`w`, `kw`, `vw`, `aw`) — `PartDB.variant_name`: id оружия и включённые карточки без префикса: `ak`, `acr+suppressor.on+mag.40`.

| `e` | Когда | Поля |
|---|---|---|
| `session` | открытие файла | `version`, `weapons_md5` (хэш `weapons.cfg` — баланс менялся → сессии не смешивать), `map`, `random_weapons`, `score_limit`, `match_time`, `dedicated` |
| `match_start` / `match_end` | матч | `match_end`: `reason`, `dur`, `scores` [{`p`, `kills`, `deaths`, `win`}] |
| `spawn` | каждое появление | `p`, `id`, `w`, `build` (все id частей) |
| `hit` | каждое попадание | `a` / `v` (кто / в кого), `aw` / `vw`, `gun` (id ствола или `melee`), `dmg` (снятое HP), `hp` (осталось), `head`, `dist`, `a_state` / `v_state` |
| `kill` | смерть | `k` / `v`, `kw` / `vw`, `gun` (`self` — самоубийство / падение), `head`, `dist`, `ttk`, `ttk_fire`, `hits`, `head_hits`, `shots`, `dmg`, `dmg_others`, `v_dmg_to_k`, `k_hp` / `k_max`, `k_life` / `v_life`, `k_state` / `v_state` |
| `life` | конец жизни (`end`: `death`, `match`, `leave`, `quit`) | `p`, `w`, `dur`, `kills`, `shots`, `hits`, `head`, `dmg_out`, `dmg_in` |

`life.hits` / `life.head` — выстрелы, попавшие хоть кем-то из дробин (в голову); до 2026-10-31 считались дробины, поэтому отчёт берёт точность из событий `hit` (одно на выстрел и жертву, у дробин одного выстрела одно `t`).

`*_state`: `speed` (м/с по горизонтали), `ads`, `crouch`, `slide`, `sprint`, `air`, `reload`.

**Как считается TTK.** Стычка жертвы — урон с момента, когда она последний раз была на полном здоровье. `ttk` — от первого попадания убийцы в этой стычке до смерти; `ttk_fire` — от начала очереди убийцы (первый выстрел после ≥ 1 с тишины), т. е. с промахами до первого попадания. `shots` — выстрелов в этой очереди. `dmg_others` — урон от других (и от прошлой жизни убийцы): > 0 — убийство не чистое. `v_dmg_to_k` > 0 — жертва успела ответить: **дуэль** (если ещё и `dmg_others` = 0), её исход — кто победил.

## Отчёт

```
python vibe-of-duty-p/tools/stats_report.py [файлы или папки] [--all] [--min=N]
```

Без путей — вся папка `stats` этого ПК. Берёт только сессии с тем же `weapons.cfg`, что у последней (`--all` — все). Таблицы: по оружию и по варианту (жизни, убийства, смерти, К/Д, дуэли выиграно/всего, медианы TTK и попаданий, точность, урон в секунду жизни, дистанция убийства); «кто кого» — убийства оружия по оружию и доля в их встречах; TTK по дистанциям 0–10 / 10–25 / 25–50 / 50+ м.

## Режим «FFA рандомное оружие» и раздел «Тестирование»

- «Создать игру» → галочка «Игровой режим: FFA рандомное оружие», доступна всем, запоминается (`Settings.host_random_weapons` → `Game.random_weapons`; выделенный сервер — `--random-weapons`). Сервер шлёт её клиентам в правилах.
- «Создать игру» → строка «Тестирование» с полем кода (тот же код, что у детского режима, `KidModeEntry`). С кодом открывается раскрывающийся раздел, как «Дополнительно», с галочкой «Записывать статистику боёв» (`Game.record_stats`). Код и галочка живут до перезапуска игры, не сохраняются.
- Каждая жизнь (первое появление, возрождение, новый матч) — случайное оружие, каждая его карточка (`PartDB.CARD_SLOTS`) вкл/выкл 50/50; сборка игрока игнорируется. Выпавшее оружие пропускает следующие 2 жизни этого игрока, потом снова в пуле (`RandomWeapons.REST`). Код — `scripts/net/random_weapons.gd`.
- В режиме скрыты выбор сборки после смерти (`BuildPicker`) и «Сборка» в паузе. На тренировках режим не действует.
