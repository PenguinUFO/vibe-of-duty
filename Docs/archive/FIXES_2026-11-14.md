## Сеть

### 1. [major] Реджойн замораживает игрока (коллизия имени узла)

**Файл:** `vibe-of-duty-p/scripts/net/world.gd`, функция `_despawn_player`, строки ~887–890.

**Проблема:** `_despawn_player` вызывает `queue_free()` (удаление только в конце кадра), но не убирает узел из дерева. Тут же в том же кадре `_spawn_player` создаёт нового игрока с `player.name = str(id)` и `add_child` — Godot видит старого «тёзку» и переименовывает нового в `5@Node3D@2`. Клиент шлёт команды по пути `World/Players/5`, на сервере такого пути больше нет → команды игрока молча отбрасываются, игрок замирает.

**Сделать** — убрать узел из дерева перед удалением:

```gdscript
@rpc("authority", "reliable")
func _despawn_player(id: int) -> void:
	if players.has(id):
		_players_root.remove_child(players[id])   # <-- добавить эту строку
		players[id].queue_free()
		players.erase(id)
```

**Проверка:** выйти и снова зайти в матч (или перезагрузить уровень, не отключаясь) — персонаж снова реагирует на ввод, не замирает.

### 3. Таймер возрождения держит `self` → ошибка «freed instance»

### 9. `damage_at` неверен для неотсортированного затухания

**Файл:** `vibe-of-duty-p/scripts/weapons/weapon_def.gd`, `damage_at`, строки ~94–99.

**Проблема:** функция перебирает все тиры и перезаписывает `mult` на каждом совпадении без `break`; при неотсортированных/немонотонных `falloff_ranges` возвращается неверный тир.

**Сделать** — возвращать на первом превышении (конфиг сортирован по возрастанию):

```gdscript
func damage_at(distance: float) -> float:
	for i in mini(falloff_ranges.size(), falloff_mults.size()):
		if distance > falloff_ranges[i]:
			return damage * falloff_mults[i]
	return damage
```

**Проверка:** урон на 31 м (первый тир 30 м) и на 51 м (второй тир 50 м) берёт правильные множители.

### 16. Рэгдолл считает «верх» через `Vector3.UP`

**Файл:** `vibe-of-duty-p/scripts/player/mannequin.gd`, `start_ragdoll`, строки ~662–672.

**Проблема:** толчок смерти и боковой разлёт используют `Vector3.UP`/`away.y = 0.0` — на кольцевой станции («Карусель») «верх» не `+Y`, направление толчка неверное (косметика).

**Сделать** — считать `up` через `Gravity.up` в точке таза:

```gdscript
	var up := Gravity.up(points[Ragdoll.PELVIS])
	var back := xf.basis.z.normalized()
	var push := back
	var strength := 1.4
	if from.is_finite():
		var away := points[Ragdoll.CHEST] - from
		away = Gravity.flat(away, points[Ragdoll.PELVIS])
		if away.length() > 0.01:
			push = away.normalized()
			strength = 3.2
	push = (push + up * 0.15).normalized() * strength
	var side := back.cross(up).normalized() * randf_range(-0.6, 0.6)  # a bit of a turn as it falls
```

**Проверка:** рэгдолл на обычных картах выглядит как раньше; на «Карусели» тело отлетает от оси, а не «в мировом вверх».

### 26. `day_cycle._mix`: нетипизированная переменная и падение при смене типа ключа

**Файл:** `vibe-of-duty-p/scripts/game/day_cycle.gd`, `_mix`, строки ~113–126.

**Проблема:** `var x = a.get(name, b[name])` нетипизирована; если тип значения ключа меняется между соседними ключами (скаляр → Dictionary), `_mix` рекурсирует в не-Dictionary и падает на `.get`.

**Сделать** — типизировать и валидировать рекурсию:

```gdscript
static func _mix(a: Dictionary, b: Dictionary, w: float) -> Dictionary:
	var out := {}
	for name in b:
		var x: Variant = a.get(name, b[name])
		var y: Variant = b[name]
		if y is Dictionary and x is Dictionary:
			out[name] = _mix(x, y, w)
		elif y is Color:
			out[name] = (x as Color).lerp(y, w)
		elif y is float or y is int:  # a scene stores 10.0 as 10
			out[name] = lerpf(float(x), float(y), w)
		else:
			out[name] = y if w >= 0.5 else x
	return out
```

**Проверка:** цикл дня/ночи на киллхаусе работает; ключ с разным типом между ключами не падает.
